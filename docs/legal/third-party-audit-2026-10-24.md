# Audit A: Third parties, cookies and storage (tassytrucks-website-v3)

Read-only code audit, 2026-10-24. Not legal advice. Facts come from code only. I did not make any network requests, so what the live site actually does is unverified (for example, whether Vercel Web Analytics is switched on in the Vercel dashboard).

## 1. Verdict

**Does the public site set any non-essential cookie or tracker before consent? No cookies, but there is one pre-consent third-party call and one pre-consent analytics script.**

- The site's own code sets NO cookies on ordinary public pages.
  - The only cookies are the `/ops` staff login cookie and the facility-partner login cookies. Both are login cookies, so they are strictly necessary, and neither is set for a normal visitor.
  - There is no consent banner anywhere. I found no "cookie" or "consent" wording in the layout, footer, privacy page or terms page (the SMS-consent wording is a separate matter).
- There are NO ad pixels or marketing tags: no Meta, Google Ads, Google Analytics, GTM, TikTok, LinkedIn, Hotjar or Clarity. I searched app/, components/, lib/, public/ and package.json and found none.
- Two things load before any consent:
  1. **Vercel Web Analytics script** on every page (`/_vercel/insights/script.js`, `app/layout.tsx:128`). It is served from our own domain and the code comment says it is "cookieless". It still collects page views, so it is a tracker in the plain sense. It does nothing unless Web Analytics is enabled on the Vercel project.
  2. **Google Maps JavaScript API** (`maps.googleapis.com`) loads in the visitor's browser as soon as a page with an address field opens (/request, /school/book/[plan], plus the facility pages after sign-in). It does not wait for a click or for consent. Loading it sends the visitor's IP address and browser details to Google, and Google may set its own cookies or storage. The code cannot show that either way, so it needs a browser check. As the visitor types an address, the typed text goes to Google.
- Fonts are self-hosted at build time via `next/font/google`. No visitor request goes to Google Fonts.
- Gaps in the privacy page (`app/privacy/page.tsx`): it names NO third party and says nothing about cookies, analytics, Google Maps, Stripe, Resend, Supabase, ntfy or Vercel. It also says nothing about the IP address and user agent that the code stores (see "Surprising" below).

## 2. Third parties

"Consent" = whether it happens before the visitor has agreed to anything (the site has no consent mechanism). "Privacy page?" = is it disclosed in `app/privacy/page.tsx`. Answer for every row unless noted: **No**. The page only says information is shared "with the people needed to complete your trip... a facility or broker... or when the law requires it".

## 4. Images, fonts, embeds, trackers

- **Image hosts (`next.config.mjs:7-9`)**: `remotePatterns` allows only `https://tassytrucksops.vercel.app`. Unsplash was removed. Every image in `<img>`/code is a local file under `public/brand/` (logos, mascots, `hirevets-2023-gold.png`, `og-image.png`, favicons) plus `public/tassy-founder.png` and `public/tassy-logo.jpg`. No absolute http(s) image URLs in the page code. Transactional emails reference images on `NEXT_PUBLIC_SITE_URL` (defaults to `https://tassytrucks-website-v3.vercel.app`), so an email open loads an image from our own host (that is a possible open-tracking signal on our own server, but there is no tracking pixel from a third party).
- **Fonts**: Newsreader and Inter via `next/font/google` (`app/layout.tsx:2,11-22`): self-hosted at build, no runtime request to Google (comment in file confirms the old Google `<link>` was removed). `globals.css` has no `@import`, `@font-face` or external `url()`.
- **Embeds**: none (no iframes; the "map" is `components/CharlotteDayMap.tsx`, an inline SVG animation with no Google/Mapbox tiles).
- **Trackers / ad tags**: **NONE found** (no Meta Pixel, Google Ads, GA/gtag, GTM, TikTok, LinkedIn Insight, Hotjar, Clarity, Hubspot, Segment). The only analytics is the Vercel Web Analytics tag.
- Booking forms record a `source` string = page path + all URL query params (utm etc.) into the database (`components/request/RequestForm.tsx:301-306`, stored in `trip_requests.source`), first-party attribution only.
- Security headers: no Content-Security-Policy and no Referrer-Policy header in `next.config.mjs`. `vercel.json` has only the two cron entries. There is no middleware file.

## 5. Surprising or worth a lawyer's attention

1. **The privacy page names no third parties and does not mention cookies or analytics at all.** It also dates itself "Last updated October 8, 2026" and carries a code comment "TODO(phil): have counsel review before any paid-acquisition push".
2. **Google Maps loads on page open, before any click or consent**, on the request form and Scholar wizard, and sends typed addresses (including a child's home address on Scholar) to Google.
3. **Health-related data is collected** (care intake, mobility, signed consent with IP and user agent stored): `app/api/trip-request/route.ts:254-260` writes the visitor's IP and user agent into the care-consent record, and `:407,540` store the user agent on every request row. The privacy page does not say IP or user agent are stored.
4. **Scholar sign-up data (child's name, school, addresses) is kept in browser sessionStorage** while the form is open. It is cleared on completion or tab close, but it is personal data about a minor in browser storage.
5. **Student/child data is sent to Stripe** only as ids in metadata, and the parent's name/email/phone as a Stripe Customer (`lib/stripe.ts:437-446`).
6. **Alerts go through public ntfy.sh.** Payloads are kept free of PII by design; the topic string is a shared secret, and the facility-signup alert includes a facility name.
7. **Two separate sites.** Applicants (`/careers`) and the main booking funnel for some lines are handed off to a different domain, `tassytrucksops.vercel.app` (`lib/saas-links.ts:33`). Its cookies and trackers are outside this repo and need their own audit. The repo's `CLAUDE.md`/docs describe that app as using a different Supabase project.
8. **Vercel Analytics tag is hand-added** (not the npm package) with the comment "Cookieless, no consent banner". Whether it is actually collecting depends on a Vercel dashboard switch that code cannot show.
9. The `/ops` page links to `maps.google.com/?q=<address>` (staff only, on click), which would send customer addresses to Google from a staff browser.
10. Environment variable names that exist (values not read or printed): SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, NEXT_PUBLIC_SITE_URL, NTFY_TOPIC, ZAPIER_SMS_WEBHOOK_URL, RESEND_API_KEY, OPERATOR_EMAIL, RESEND_FROM_EMAIL, CRON_SECRET, OPS_PASSWORD, GOOGLE_MAPS_API_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, plus TASSYOPS_NOTIFY_URL and INTERNAL_NOTIFY_SECRET (referenced in `lib/tassyops-notify.ts`).
